# domainatoredux


## Plan

Rewrite domainator from the ground up in rust.

### key improvements
 - better cross-platform support
    - include support for windows, linux
 - single executable CLI call
    - domainator [tool name] [tool options ...]
- Rich cross platform GUI
    - use tauri
    - second executable domainator_gui
- Better support for integration with agentic workflows


### Hard requirement
- maintain compatibility with input and output files generated by original domainator
    - genbank files
    - hdf files
    - formatted databases
        - shards, bgzip, indexes


### implementation

Prioritize the pipeline for building sequence similarity networks.  and analyzing their results

- step 1: port the domainator vendored biopython genbank parser and SeqRecord to pure rust
    - can also re-imagine the internal sequence representation data structures
- step 2: port domainate.py and domain_search.py
- step 3: port seq_dist.py and compare_contigs.py
- step 4: build a gui with tauri
        - inspired by Geneious: see external/screenshots/geneious.png
        - make a much better contig viewer than the current plot_contigs.py
        - integrate an SSN viewer similar to (or exactly the same as) the output from build_ssn_viewer.py
- step 5: take a break and evaluate progress before continuing

### Deferred

There are some dependencies that are not easily portable to Rust, such as anything using torch. Also, Infernal, and several other dependencies. These are outside the scope of the first release.
